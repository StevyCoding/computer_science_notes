# Backing Up etcd
Here's a concise summary of the etcd backup process described:

1. **SSH Access:** Connected to the `kube-control-plane` node (Ubuntu 24.04 LTS) via SSH.
    
2. **Version Check:** Verified `etcdctl` and etcd Pod versions (both 3.5.15).
    
3. **Configuration Details:** Retrieved etcd configuration using `kubectl describe pod`, including:
    
    - Client URL: `localhost:2379`
        
    - Certificates and key paths:
        
        - CA cert: `/etc/kubernetes/pki/etcd/ca.crt`
            
        - Server cert: `/etc/kubernetes/pki/etcd/server.crt`
            
        - Server key: `/etc/kubernetes/pki/etcd/server.key`
            
4. **Creating Backup:** Used `etcdctl` with `ETCDCTL_API=3` to create a snapshot:
    
    - Output file: `/opt/etcd-backup.db`
        
    - Authenticated using the specified cert, key, and CA files.
        
5. **Session Ended:** Closed the SSH session with `exit`.
    
# Restoring etcd
### **etcd Restore from Backup – Summary**

1. **Purpose of Backup:**  
    The etcd backup serves as a recovery tool in case of data corruption or physical storage failure.
    
2. **Restoration Tool:**  
    Use `etcdutl snapshot restore` instead of the deprecated `etcdctl` restore command (removed in etcd 3.6+).
    
3. **Restore Command:**  
    Restore the snapshot to a new data directory, e.g.:
    
    ```bash
    sudo ETCDCTL_API=3 etcdutl --data-dir=/var/lib/from-backup snapshot restore /opt/etcd-backup.db
    ```
    
4. **Verify Restored Data:**  
    After restoration, the directory `/var/lib/from-backup` should contain a `member` folder.
    
5. **Update etcd Pod Manifest:**  
    Edit `/etc/kubernetes/manifests/etcd.yaml`:
    
    - Change the `spec.volumes.hostPath.path` for volume `etcd-data` from `/var/lib/etcd` to `/var/lib/from-backup`.
        
6. **Pod Recreation:**  
    The `etcd-kube-control-plane` Pod will automatically restart using the restored data.
    
    - If it fails to start, delete the Pod manually:
        
        ```bash
        kubectl delete pod etcd-kube-control-plane -n kube-system
        ```
        
7. **Exit Node:**  
    Use `exit` to leave the SSH session.
