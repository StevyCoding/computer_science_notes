### Access Modifiers

An access modifier determines what classes a method can be accessed from. Think of it like a security guard. Some classes are good friends, some are distant relatives, and some are complete strangers. Access modifiers help to enforce when these components are allowed to talk to each other. Java offers four choices of access modifier:

- **private** The `private` modifier means the method can be called only from within the same class.
- **Package Access** With package access, the method can be called only from a class in the same package. This one is tricky because there is no keyword. You simply omit the access modifier. Package access is sometimes referred to as package-private or default access (even within this book!).
- **protected** The `protected` modifier means the method can be called only from a class in the same package or a subclass.
- **public** The `public` modifier means the method can be called from anywhere.

### Instance Variable Modifiers

Like methods, instance variables can use access modifiers, such as `private`, package, `protected`, and `public`. Remember, package access is indicated by the lack of any modifiers. We cover each of the different access modifiers shortly in this chapter. Instance variables can also use optional specifiers, described in Table 5.3.

Since Java passes object references by value, it is essential to understand how data is copied and modified. Let's explore a more detailed look at this topic.

## Passing Object References By Value

When you pass an object reference to a method in Java, you are not passing the object itself. Instead, you are passing a *copy of the reference*. This means that the method receives a copy of the reference that points to the same object in memory.

Here's a breakdown of what happens when you pass an object reference:

1.  **Copy of the Reference:** Java creates a copy of the object's reference.
2.  **Method Receives Copy:** The method receives this copy of the reference.
3.  **Changes Inside Method:** Any modifications made to the object's fields inside the method affect the original object because both the original reference and the copy reference point to the same object in memory.
4.  **No Change to Original Reference:** The original reference in the calling method remains unchanged.

Let's illustrate this with an example:

```javascript
class Dog {
    name;

    constructor(name) {
        this.name = name;
    }
}

function changeDogName(dog) {
    dog.name = "Champ"; // Modifies the object's name
}

const myDog = new Dog("Buddy");
changeDogName(myDog);
console.log(myDog.name); // Output: Champ
```

## Understanding the Key Difference

The key difference between passing by value and passing by reference is that in passing by value, a copy of the value is created, while in passing by reference, the original variable is directly accessed.

To further solidify this concept, let's consider another example:

```javascript
class Person {
    name;

    constructor(name) {
        this.name = name;
    }
}

function modifyPerson(p) {
    p.name = "Bob"; // Modifies the object's name
}

const person1 = new Person("Alice");
modifyPerson(person1);
console.log(person1.name); // Output: Bob
```
