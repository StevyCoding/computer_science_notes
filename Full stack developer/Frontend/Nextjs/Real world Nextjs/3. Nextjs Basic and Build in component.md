## Routing System

### Next.js Routing: Filesystem-Based Approach

Unlike React Router, which handles only client-side routing, Next.js uses a filesystem-based routing system. Each file in the `pages/` directory automatically becomes a route.

For example:

- `pages/index.js` → Accessible at `/`
- `pages/contact-us.js` → Accessible at `/contact-us`
- Renaming `contacts.js` to `contact-us.js` automatically updates the route.

### Nested & Dynamic Routes

Next.js also supports nested and dynamic routes:

- `pages/posts/index.js` → Accessible at `/posts`
- `pages/posts/[slug].js` → Accessible at `/posts/:slug` (e.g., `/posts/my-first-post`)

For deeper nesting:

- `pages/posts/[date]/[slug].js` → Accessible at `/posts/:date/:slug` (e.g., `/posts/2021-01-01/my-first-post`)

Dynamic routes allow rendering different content based on URL parameters, which we will explore further.

**Using route variables inside our pages**

Route variables are incredibly useful for creating very dynamic page content.

Let's take an easy example: a greetings page. Inside the project used in the previous section, let's create the following file: **pages/greet/[name].js**. We're going to use Next.js' built-in **getServerSideProps** function to dynamically get the **[name]** variable from the URL and greet the user:

```jsx
export async function getServerSideProps({ params }) {

const { name } = params;

return {

props: {

name

}

}

}

function Greet(props) {

return (

<h1> Hello, {props.name}! </h1>

)

}
export default Greet;
```

Now, open your favorite browser and go to [http://localhost:3000/greet/Mitch](http://localhost:3000/greet/Mitch); you should see a "**Hello, Mitch!**" message appear on the screen. Remember that we're using a **name** variable, so feel free to try with some different names!

Extracting data from the URL is essential for many applications. While our previous example displayed a simple greeting, we could use the `[name]` variable to fetch user data from a database and display their profile.

We'll explore data fetching in more detail in **Chapter 4**.

Sometimes, we need to access route variables within components instead of pages. Next.js simplifies this with a built-in React hook, which we’ll explore next. 🚀

## Using route variables inside components

While `getServerSideProps` and `getStaticProps` can only be used in pages, Next.js provides the `useRouter` hook for accessing route variables inside components.

### Refactoring the Greeting Page

We can extract the route variable using `useRouter`:

```jsx
import { useRouter } from 'next/router';

function Greet() {
  const { query } = useRouter();
  return <h1>Hello {query.name}!</h1>;
}

export default Greet;

```

### Accessing Query Parameters

The `query` object contains both route variables and query string parameters. Logging `query` reveals all values passed in the URL:

```jsx
import { useRouter } from 'next/router';

function Greet() {
  const { query } = useRouter();
  console.log(query);
  return <h1>Hello {query.name}!</h1>;
}

export default Greet;

```

### Example URL & Output

Visiting `http://localhost:3000/greet/Mitch?learning_nextjs=true` logs:

```json
{ "name": "Mitch", "learning_nextjs": "true" }

```

This approach allows components to dynamically respond to URL parameters without needing page-level data fetching! 🚀

# Client-side navigation

Next.js enhances performance by optimizing client-side navigation. While standard `<a>` tags work, the `Link` component provides better efficiency by preloading pages in the viewport.

### Basic Example of `Link` Component

```jsx
import Link from 'next/link';

function Navbar() {
  return (
    <div>
      <Link href='/'>Home</Link>
      <Link href='/about'>About</Link>
      <Link href='/contacts'>Contacts</Link>
    </div>
  );
}

export default Navbar;

```

By default, Next.js **preloads linked pages**, improving navigation speed. You can disable preloading using `preload={false}`:

```jsx
<Link href='/about' preload={false}>About</Link>

```

---

### Dynamic Route Links

Starting with Next.js 10, linking to dynamic routes became easier.

### Before Next.js 10 (Legacy Approach)

```jsx
<Link href='/blog/[date]/[slug]' as='/blog/2021-01-01/happy-new-year'>
  Read post
</Link>

```

The `as` prop was required to format the URL correctly.

### Next.js 10+ (Simplified Approach)

```jsx
<Link href='/blog/2021-01-01/happy-new-year'>Read post</Link>
<Link href='/blog/2021-03-05/match-update'>Read post</Link>
<Link href='/blog/2021-04-23/i-love-nextjs'>Read post</Link>

```

Now, `href` alone handles both routing and URL formatting.

---

### **Passing Objects to `href` for Complex URLs**

For dynamically building URLs, use an object format:

```jsx
<Link
  href={{
    pathname: '/blog/[date]/[slug]',
    query: { date: '2020-01-01', slug: 'happy-new-year', foo: 'bar' }
  }}
>
  Read post
</Link>

```

This generates the URL:

📍 `http://localhost:3000/blog/2020-01-01/happy-new-year?foo=bar`

🚀 **Tip:** If you're upgrading from an older Next.js version, remember that `as` is no longer needed for dynamic routes!

## Using the router.push method

We can use the `useRouter` hook to redirect unauthenticated users dynamically by checking their login status with the `useAuth` hook.

```jsx
import { useEffect } from 'react';

import { useRouter } from 'next/router';

import PrivateComponent from '../components/Private';

import useAuth from '../hooks/auth';

function MyPage() {

  const router = useRouter();

  const { loggedIn } = useAuth();

  useEffect(() => {

    if (!loggedIn) {

      router.push('/login')

    }

  }, [loggedIn]);

  return loggedIn

    ? <PrivateComponent />

    : null;

}

export default MyPage;
```

## Nextjs automatic image optimization

Next.js 10 introduced an **Image component** and **automatic image optimization**, simplifying the process of serving optimized, responsive images. Previously, developers had to manually optimize images and use the `srcset` attribute for responsive images. Next.js now handles this automatically, serving modern formats like WebP to supported browsers and falling back to older formats like JPEG or PNG for unsupported ones. It also resizes images to improve load times.

This optimization happens **on-demand**, meaning images are only processed when requested by the browser, avoiding slowdowns during the build phase. It works seamlessly with external data sources like CMS platforms or image services (e.g., Unsplash, Pexels).

To use this feature, configure the `next.config.js` file to allow images from specific domains, such as Unsplash:

```jsx
module.exports = {
  images: {
    domains: ['images.unsplash.com'],
  },
};

```

Then, use the `Image` component in your pages:

```jsx
import Image from 'next/image';

function IndexPage() {
  return (
    <div>
      <Image
        src='<https://images.unsplash.com/photo-1605460375648-278bcbd579a6>'
        width={500}
        height={200}
        alt='A beautiful English Setter'
      />
    </div>
  );
}

export default IndexPage;

```

The `Image` component supports responsive behavior through the `layout` prop, which accepts four values:

- **fixed**: Maintains the same size regardless of viewport.
- **responsive**: Adjusts image size based on viewport.
- **intrinsic**: Resizes for smaller screens but keeps the original size on larger screens.
- **fill**: Stretches the image to fit its parent container (requires removing `width` and `height` props).

For example, to crop an image to fit a specific container:

```jsx
import Image from 'next/image';

function IndexPage() {
  return (
    <div style={{ width: 500, height: 200, position: 'relative' }}>
      <Image
        src='<https://images.unsplash.com/photo-1605460375648-278bcbd579a6>'
        layout='fill'
        objectFit='cover'
        alt='A beautiful English Setter'
      />
    </div>
  );
}

export default IndexPage;

```

The `Image` component generates multiple image sizes and serves them using the `srcset` attribute. It also automatically serves images in the most efficient format (e.g., WebP for Chrome/Firefox, JPEG for Safari).

Since optimization occurs on the server, it can impact performance for image-heavy apps. In such cases, offloading optimization to external services may be beneficial.

## Running automatic image optimization on external services

By default, Next.js performs **automatic image optimization** on the same server where your application runs. However, this can strain server resources, especially on smaller or low-powered servers. To address this, Next.js allows you to offload image optimization to **external services** by configuring the `loader` option in the `next.config.js` file. For example:

```jsx
module.exports = {
  images: {
    loader: 'akamai',
    domains: ['images.unsplash.com'],
  },
};

```

If you deploy your app on **Vercel**, no additional configuration is needed, as Vercel handles image optimization automatically. Otherwise, you can use external services like:

- **Akamai**: [](https://www.akamai.com/)[https://www.akamai.com](https://www.akamai.com)
- **Imgix**: [](https://www.imgix.com/)[https://www.imgix.com](https://www.imgix.com)
- **Cloudinary**: [](https://cloudinary.com/)[https://cloudinary.com](https://cloudinary.com)

For custom image optimization servers or open-source solutions like **Imgproxy** or **Thumbor**, you can define a custom `loader` directly in your component:

```jsx
import Image from 'next/image';

const loader = ({ src, width, quality }) => {
  return `https://example.com/${src}?w=${width}&q=${quality || 75}`;
};

function CustomImage() {
  return (
    <Image
      loader={loader}
      src="/myimage.png"
      alt="My image alt text"
      width={350}
      height={540}
    />
  );
}

```

Each service has its own API for resizing and serving images. For example:

- **Imgproxy**: `https://imgproxy.example.com/<auth-key>/fill/500/500/sm/0/plain/<https://example.com/images/myImage.jpg`>
- **Thumbor**: `https://thumbor.example.com/500x500/smart/example.com/images/myImage.jpg`

Before implementing a custom loader, consult the documentation of your chosen image optimization service to ensure proper integration.

Optimizing image delivery is crucial for improving user experience, and Next.js simplifies this process with its built-in tools. However, it's also important to consider **metadata handling** for web scrapers, bots, and spiders, which rely on metadata for indexing and evaluation. We'll explore metadata management in the next section.

To resolve the issue of potential duplicate metadata tags and ensure dynamic title updates work correctly in the Next.js application, follow these steps:

1. **Add `key` Prop to Title Tags**: Assign a consistent `key` prop to all `<title>` elements. This tells Next.js to replace the existing tag with the same key instead of duplicating it.

2. **Update Page Components**: Modify the `index.js` and `about.js` pages to include the `key` prop in their respective `<title>` tags.

3. **Modify the Widget Component**: Ensure the dynamic title in the `Widget` component also uses the same `key` prop.

**Here's the revised code:**

**components/Widget.js:**
```javascript
import { useState } from 'react';
import Head from 'next/head';

function Widget({ pageName }) {
  const [active, setActive] = useState(false);

  return (
    <>
      {active && (
        <Head>
          <title key="title">You're browsing the {pageName} page</title>
        </Head>
      )}
      <div>
        {active ? (
          <>
            <button onClick={() => setActive(false)}>
              Restore original title
            </button>
            <p>Take a look at the title!</p>
          </>
        ) : (
          <button onClick={() => setActive(true)}>
            Change page title
          </button>
        )}
      </div>
    </>
  );
}

export default Widget;
```

**pages/index.js:**
```javascript
import Head from 'next/head';
import Link from 'next/link';
import Widget from '../components/Widget';

function IndexPage() {
  return (
    <>
      <Head>
        <title key="title">Welcome to my Next.js website</title>
      </Head>
      <div>
        <Link href="/about" passHref>
          <a>About us</a>
        </Link>
      </div>
      <div>
        <Widget pageName="index" />
      </div>
    </>
  );
}

export default IndexPage;
```

**pages/about.js:**
```javascript
import Head from 'next/head';
import Link from 'next/link';
import Widget from '../components/Widget';

function AboutPage() {
  return (
    <>
      <Head>
        <title key="title">About this website</title>
      </Head>
      <div>
        <Link href="/" passHref>
          <a>Back to home</a>
        </Link>
      </div>
      <div>
        <Widget pageName="about" />
      </div>
    </>
  );
}

export default AboutPage;
```

**Key Changes Explained:**
- **Consistent `key` Usage**: All `<title>` tags now have `key="title"`, ensuring Next.js replaces the existing title instead of duplicating it.
- **Conditional Rendering in Widget**: The dynamic title is only rendered when `active` is `true`, and the `key` ensures it overrides the original title.
- **State Management**: The `active` state toggles between displaying the dynamic and original titles without conflicts.

**Testing the Solution:**
- Navigate between `/` and `/about` to see the original titles.
- Click "Change page title" to see the dynamic title with the page name.
- Click "Restore original title" to revert back, ensuring no duplicate `<title>` tags in the HTML `<head>`.

This approach leverages Next.js's `Head` component effectively, using keys to manage dynamic metadata and prevent duplication.

## Grouping common metadata

To avoid duplicating common meta tags across multiple pages, we can centralize the metadata handling by customizing the `_app.js` file in Next.js. This file is the root component of your application, and any modifications here will apply to all pages. By adding shared meta tags here, we ensure consistency and reduce redundancy.

Here’s how you can implement this:

---

### Step 1: Customize `_app.js`

Create or modify the `_app.js` file in the `pages` directory to include shared meta tags. These tags will be applied to every page by default.

```javascript
// pages/_app.js
import Head from 'next/head';
import '../styles/globals.css'; // Import global styles if needed

function MyApp({ Component, pageProps }) {
  return (
    <>
      <Head>
        {/* Common meta tags */}
        <meta charSet="UTF-8" />
        <meta name="viewport" content="width=device-width, initial-scale=1.0" />
        <meta name="description" content="Your default website description" />
        <meta name="keywords" content="your, default, keywords" />
        <meta name="author" content="Your Name" />

        {/* Open Graph meta tags (default) */}
        <meta property="og:type" content="website" />
        <meta property="og:site_name" content="Your Website Name" />
        <meta property="og:image" content="https://yourwebsite.com/default-image.jpg" />

        {/* Twitter Card meta tags (default) */}
        <meta name="twitter:card" content="summary" />
        <meta name="twitter:site" content="@yourtwitterhandle" />
        <meta name="twitter:creator" content="@yourtwitterhandle" />
      </Head>
      <Component {...pageProps} />
    </>
  );
}

export default MyApp;
```

---

### Step 2: Override Default Meta Tags in Specific Pages

While the shared meta tags in `_app.js` provide a default configuration, you can override them in individual pages or components using the `Head` component. For example, in the `[slug].js` blog post page, you can dynamically set page-specific meta tags:

```javascript
// pages/blog/[slug].js
import PostHead from '../../components/PostHead';
import posts from '../../data/posts';

export function getServerSideProps({ params }) {
  const { slug } = params;
  const post = posts.find((p) => p.slug === slug);
  return {
    props: {
      post,
    },
  };
}

function Post({ post }) {
  return (
    <div>
      <PostHead {...post} />
      <h1>{post.title}</h1>
      <p>{post.subtitle}</p>
    </div>
  );
}

export default Post;
```

---

### Step 3: Use the `PostHead` Component for Blog-Specific Metadata

The `PostHead` component (created earlier) dynamically sets meta tags for blog posts. This component will override the default meta tags defined in `_app.js` for the specific blog post being viewed.

```javascript
// components/PostHead.js
import Head from 'next/head';

function PostHead(props) {
  return (
    <Head>
      <title key="title">{props.title}</title>
      <meta name="description" content={props.subtitle} />

      {/* Open Graph meta */}
      <meta property="og:title" content={props.title} />
      <meta property="og:description" content={props.subtitle} />
      <meta property="og:image" content={props.image} />

      {/* Twitter Card meta */}
      <meta name="twitter:card" content="summary" />
      <meta name="twitter:title" content={props.title} />
      <meta name="twitter:description" content={props.subtitle} />
      <meta name="twitter:image" content={props.image} />
    </Head>
  );
}

export default PostHead;
```

### Step 4: Test the Implementation

1. Run your Next.js application.
2. Navigate to different pages (e.g., `/`, `/about`, `/blog/dog-of-the-day-the-english-setter`).
3. Inspect the `<head>` section of the HTML to verify that:
   - Default meta tags are present on all pages.
   - Page-specific meta tags override the defaults where applicable.

2. **Dynamic Overrides**: Pages and components can override default meta tags as needed.

# Customizing \_app.js and \_document.js pages

In Next.js, there are scenarios where you need to control page initialization, ensuring specific operations run before rendering the HTML sent to the client. This is achieved by customizing two key files: `_app.js` and `_document.js`, located in the `pages/` directory.

---

## The \_app.js Page

By default, Next.js includes a basic `_app.js` file:

```javascript
import '../styles/globals.css';

function MyApp({ Component, pageProps }) {
  return <Component {...pageProps} />;
}

export default MyApp;
```

This file renders the page component (`Component`) and its props (`pageProps`). To share a navigation bar across all pages, you can create a `Navbar` component and include it in `_app.js`:

```javascript
import Navbar from '../components/Navbar';

function MyApp({ Component, pageProps }) {
  return (
    <>
      <Navbar />
      <Component {...pageProps} />
    </>
  );
}

export default MyApp;
```

The `Navbar` component can include links for navigation:

```javascript
import Link from 'next/link';

function Navbar() {
  return (
    <div style={{ display: 'flex', justifyContent: 'space-between', marginBottom: 25 }}>
      <div>My Website</div>
      <div>
        <Link href="/">Home</Link>
        <Link href="/about">About</Link>
        <Link href="/contacts">Contacts</Link>
      </div>
    </div>
  );
}

export default Navbar;
```

To add theme support (e.g., dark/light mode), you can use React context. First, create a `ThemeContext`:

```javascript
import { createContext } from 'react';

const ThemeContext = createContext({
  theme: 'light',
  toggleTheme: () => null,
});

export default ThemeContext;
```

Then, update `_app.js` to include theme state and styles:

```javascript
import { useState } from 'react';
import ThemeContext from '../components/themeContext';
import Navbar from '../components/Navbar';

const themes = {
  dark: { background: 'black', color: 'white' },
  light: { background: 'white', color: 'black' },
};

function MyApp({ Component, pageProps }) {
  const [theme, setTheme] = useState('light');
  const toggleTheme = () => setTheme(theme === 'dark' ? 'light' : 'dark');

  return (
    <ThemeContext.Provider value={{ theme, toggleTheme }}>
      <div style={{ width: '100%', minHeight: '100vh', ...themes[theme] }}>
        <Navbar />
        <Component {...pageProps} />
      </div>
    </ThemeContext.Provider>
  );
}

export default MyApp;
```

Add a theme toggle button to the `Navbar`:

```javascript
import { useContext } from 'react';
import Link from 'next/link';
import ThemeContext from '../components/themeContext';

function Navbar() {
  const { toggleTheme, theme } = useContext(ThemeContext);
  const newThemeName = theme === 'dark' ? 'light' : 'dark';

  return (
    <div style={{ display: 'flex', justifyContent: 'space-between', marginBottom: 25 }}>
      <div>My Website</div>
      <div>
        <Link href="/">Home</Link>
        <Link href="/about">About</Link>
        <Link href="/contacts">Contacts</Link>
        <button onClick={toggleTheme}>Set {newThemeName} theme</button>
      </div>
    </div>
  );
}

export default Navbar;
```

This setup ensures the theme state persists across page navigations.

---

### Key Notes on \_app.js

- **Purpose**: Maintain state between pages, add global styles, handle layouts, or inject additional data into page props.
- **Data Fetching**: Avoid using `getServerSideProps` or `getStaticProps` in `_app.js`. Use `getInitialProps` if necessary, but this disables automatic static optimization.

Example of `getInitialProps` in `_app.js`:

```javascript
import App from 'next/app';

function MyApp({ Component, pageProps }) {
  return <Component {...pageProps} />;
}

MyApp.getInitialProps = async (appContext) => {
  const appProps = await App.getInitialProps(appContext);
  const additionalProps = await fetch(...); // Fetch additional data
  return { ...appProps, ...additionalProps };
};

export default MyApp;
```

### The \_document.js Page

While `_app.js` customizes page rendering, `_document.js` allows you to modify the HTML document structure, including `<html>` and `<body>` tags. Create a `_document.js` file in the `pages/` directory:

```javascript
import Document, { Html, Head, Main, NextScript } from 'next/document';

class MyDocument extends Document {
  static async getInitialProps(ctx) {
    const initialProps = await Document.getInitialProps(ctx);
    return { ...initialProps };
  }

  render() {
    return (
      <Html lang="en">
        <Head />
        <body>
          <Main />
          <NextScript />
        </body>
      </Html>
    );
  }
}

export default MyDocument;
```

---

### Key Components of  \_document.js

1. **Html**: Represents the `<html>` tag. You can pass attributes like `lang`.
2. **Head**: Adds global tags (e.g., `<meta>`, `<link>`). This is different from the `Head` component used in pages.
3. **Main**: Renders the page components.
4. **NextScript**: Injects necessary JavaScript for client-side functionality.

---

### Important Notes on  \_document.js

- **Mandatory Components**: Removing `Html`, `Head`, `Main`, or `NextScript` will break the application.
- **No Data Fetching**: Avoid using `getServerSideProps` or `getStaticProps` in `_document.js`. Use `getInitialProps` sparingly, as it disables static optimization.
