Web development has evolved significantly with modern JavaScript frameworks like Angular, React, and Vue. React, created at Facebook, revolutionized frontend development by introducing reusable components. However, **its client-side rendering posed SEO and performance challenges**. To address this, Vercel introduced Next.js, enabling server-side rendering, automatic code-splitting, and other powerful features. Today, Next.js is widely adopted by major companies like Netflix and Uber, showcasing its versatility in building scalable applications. While it’s a leading solution, other server-side rendering frameworks also exist.

Today, Next.js provides tons of new features out of the box, such as the following:

- Static site generation
- Incremental static generation
- Native TypeScript support
- Automatic polyfills
- Image optimization
- Support for internationalization
- Performance analytics

Next.js, with its powerful features, is widely used by top companies like Netflix, Twitch, and Uber. Its versatility makes it a go-to choice for businesses of all sizes, though other server-side rendering frameworks also exist.

# Comparing Nextjs to other alternative

- **Gatsby**
    - Ideal for static site generation
    - Pre-renders pages at build time for high performance
    - Works well with Content Delivery Networks (CDNs)
    - Lacks dynamic server-side rendering capabilities
- **Razzle**
    - Framework-agnostic (supports React, Vue, Angular, etc.)
    - Simplifies server-side rendering without complex setup
    - Aims to provide an experience similar to create-react-app
    - Less popular compared to Next.js
- **Nuxt.js**
    - Best suited for Vue developers
    - Supports server-side rendering and static site generation
    - Requires more configuration but offers flexibility
    - Shares many features with Next.js but built on Vue
- **Angular Universal**
    - Official server-side rendering solution for Angular
    - Developed and maintained by Google
    - Supports both static site generation and SSR
    - Ideal for existing Angular projects needing better SEO and performance

# Moving from React to Next.js

Next.js builds on your existing React experience by offering a **convention-over-configuration** approach that simplifies creating your first website. It lets you easily designate pages for **server-side rendering** or **static generation** by exporting specific functions, eliminating the need for complex configuration files. Unlike React—a library—Next.js is a full **framework** that delivers robust tools for building rich user experiences on both client and server sides, though it runs on Node.js and lacks browser-specific globals like **window** and **document**. Additionally, it supports Node.js APIs such as **fs** and **child_process**, and even if you're aiming for a client-side rendered app, Next.js provides built-in components and optimizations for progressive, offline-first applications.

- **Convention-over-Configuration:** Simplifies setup with sensible defaults.
- **Server-Side Rendering & Static Generation:** Easily choose rendering methods per page.
- **Full-Featured Framework:** Offers a complete toolset beyond React’s library scope.
- **Node.js Environment Considerations:** Operates without browser globals like **window** and **document**.
- **Support for Node.js APIs:** Allows use of modules like **fs** and **child_process**.
- **Progressive Web App Capabilities:** Facilitates development of offline-first, progressive web applications.

# Getting start with nextjs

Getting started with **Next.js** is simple—just install **Node.js** and **npm**. The **create-next-app** tool, developed by Vercel, quickly generates a boilerplate project with all dependencies installed. Running `npx create-next-app <app-name>` sets up the project, and `npm run dev` launches a development server on **port 3000**.

By default, Next.js uses **Yarn**, but you can force it to use **npm** with `--use-npm`. Additionally, the tool supports initializing projects with example templates from the **Next.js GitHub repository**, such as `npx create-next-app <app-name> --example with-docker`, which downloads a Docker-integrated setup.

The default project structure includes:

- **pages/**: Each JavaScript file inside becomes a public page (e.g., `about.js` creates `localhost:3000/about`).
- **public/**: Stores static assets like images, fonts, and stylesheets.
- **styles/**: Contains optional CSS files for organizing styles.

Beyond the default setup, you can add directories like **components/** and **utilities/** without affecting Next.js functionality. If you prefer, you can also manually set up a Next.js project by installing the required dependencies in an existing React app, making it highly flexible.

## TypeScript integration

Next.js is written in **TypeScript** and provides **built-in type definitions** for an improved developer experience. To enable TypeScript, simply create a **tsconfig.json** file in the root of your project. Running `npm run dev` will prompt you to install the necessary dependencies:

```
npm install --save typescript @types/react
```

Once installed, Next.js will automatically populate **tsconfig.json** with default configurations, which can be customized. However, since Next.js uses **Babel** to handle TypeScript, there are some **caveats**:

- **const enum** is not supported; use `babel-plugin-const-enum` for support.
- **export = and import =** are not allowed; instead, use ECMAScript module syntax.

For more details, refer to the official Babel documentation:  
[TypeScript Caveats](https://babeljs.io/docs/en/babel-plugin-transform-typescript#caveats)  
[Compiler Options](https://babeljs.io/docs/en/babel-plugin-transform-typescript#typescript-compiler-options)

Additionally, Next.js generates a **next-env.d.ts** file in the project root, which should not be deleted, as it ensures TypeScript works smoothly within the framework.

## Custom Babel and webpack configuration

Next.js allows you to customize both **Babel** and **Webpack** to modify how your app is transpiled and bundled.

### Customizing Babel

Babel is used to transform modern JavaScript into backward-compatible code for older browsers. You can customize Next.js' default Babel settings by creating a `.babelrc` file in your project root:

```json
{
  "presets": ["next/babel"]
}
```

To enable experimental features like the **pipeline operator**, install the required plugin:

```sh
npm install --save-dev @babel/plugin-proposal-pipeline-operator @babel/core
```

Then update `.babelrc`:

```json
{
  "presets": ["next/babel"],
  "plugins": [
    [
      "@babel/plugin-proposal-pipeline-operator",
      { "proposal": "fsharp" }
    ]
  ]
}
```

### Customizing Webpack

Webpack bundles all project files and assets into optimized output. You can modify its settings by creating a `next.config.js` file:

```js
module.exports = {
  webpack: (config, options) => {
    config.module.rules.push({
      test: /\.js/,
      use: [
        options.defaultLoaders.babel,
        {
          loader: "my-custom-loader",
          options: {} // Add custom options here
        }
      ]
    });
    return config;
  }
};
```

By modifying Webpack, you can integrate **CSS preprocessors (SASS/LESS)**, add custom loaders, and extend Next.js' default settings. However, Next.js follows a **convention-over-configuration** approach, so most projects don't need customization unless advanced modifications are required.
