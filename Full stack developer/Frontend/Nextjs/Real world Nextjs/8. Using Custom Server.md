# Integrating a Custom Server with Next.js

## Introduction

- Next.js is a powerful framework that allows you to create server-side rendered web applications without the need for a custom server.
- However, there are cases where you might need to use a custom server, such as integrating with an existing backend or adding custom server-side logic.

## When to Use a Custom Server

- **Integrating with an Existing Backend**: If your application needs to interact with a backend server that is not built with Next.js, you may need to create a custom server.
- **Implementing Custom Server-Side Logic**: If your application requires specific server-side functionality that is not provided by Next.js, a custom server can be used to add that logic.
- **Handling Websockets or other Real-Time Protocols**: Next.js's built-in server does not support real-time protocols like WebSockets. A custom server can be used to handle these use cases.

## Options for Custom Servers

1. **Express.js**: A popular and flexible web application framework for Node.js that can be integrated with Next.js.
2. **Fastify**: A modern, fast, and low-overhead web framework for Node.js that can also be used with Next.js.

## Deployment Considerations

- **Process Management**: Use a process manager like PM2 or systemd to manage the custom server process.
- **Reverse Proxy**: Use a reverse proxy like Nginx to handle SSL/TLS termination and load balancing.
- **Environment Variables**: Make sure to set environment variables for production, such as the `NODE_ENV` variable.

By integrating a custom server with Next.js, you can extend the functionality of your application and handle scenarios that are not natively supported by Next.js's built-in server. This can be particularly useful when working with existing backends or implementing custom server-side logic.

The choice between using Express.js or Fastify as the custom server depends on your personal preference and the specific requirements of your project. Both frameworks provide a flexible and powerful way to extend the capabilities of your Next.js application.

# About using a custom server

## Key Points:

- Next.js includes its own server by default, making custom servers unnecessary for most applications
- Custom servers (Express.js, Fastify) are possible through Next.js APIs

## When to Use Custom Servers:

1. **Integrating with existing applications** - Keep your current server-side logic while progressively adopting Next.js
2. **Multi-tenancy needs** - When handling many domains requires more control than Next.js's native solutions
3. **Architecture preferences** - When you want to organize backend code differently (e.g., MVC pattern)

## Drawbacks:

- Cannot deploy to Vercel (Next.js's optimized hosting platform)
- Requires more code to write and maintain
- Adds complexity to smaller projects or teams

Custom servers should be considered only when Next.js's built-in capabilities don't meet specific requirements for your application.

# Using a custom Express.js server

## Setup Process:

1. Install dependencies: `yarn add express react react-dom next`
2. Create an `index.js` file with required imports:
   ```javascript
   const { parse } = require('url');
   const express = require('express');
   const next = require('next');
   ```
3. Initialize the Next.js app:
   ```javascript
   const dev = process.env.NODE_ENV !== 'production';
   const app = next({ dev });
   ```

## Server Implementation:

- Create a main function that:
  - Prepares the Next.js app
  - Gets the request handler
  - Sets up Express routes
  - Listens on port 3000

## Key Functionality:

- You can create standard Next.js pages in the `pages/` directory
- Dynamic routes work normally (e.g., `pages/greet/[user].js`)
- You can mix Express routes with Next.js pages:
  ```javascript
  server
    .get('/', (req, res) => {
      res.send('Hello World!'); // Express route
    })
    .get('/about', (req, res) => {
      app.render(req, res, '/about', query); // Next.js page
    })
  ```

## Important Consideration:

- Must handle static assets with a route for `/_next/` paths:
  ```javascript
  .get(/_next\/.+/, (req, res) => {
    const parsedUrl = parse(req.url, true);
    handle(req, res, parsedUrl);
  })
  ```
- Without this, Next.js pages will render but appear blank (missing scripts)

This approach allows progressive migration of existing Express apps to Next.js while maintaining full control over server-side functionality.

# Using a custom Fastify server

## Why Choose Fastify?

- Extremely fast performance compared to Express.js, Koa, and Hapi
- Developed by Node.js core team members (including Matteo Collina)
- Excellent developer experience with strong best practices
- Robust plugin system

## Setup Process:

1. Install dependencies: `yarn add react react-dom fastify fastify-nextjs next`
2. Create standard Next.js pages in the `/pages` directory
3. Implement your Fastify server:
   ```javascript
   const fastify = require('fastify')();
   
   fastify
     .register(require('fastify-nextjs'))
     .after(() => {
       fastify.next('/');
       fastify.next('/about');
       fastify.next('/greet/:user');
     });
   
   fastify.listen(3000);
   ```

## Key Advantages Over Express Implementation:

- Simpler integration with the official `fastify-nextjs` plugin
- No need to manually handle Next.js static assets
- Clean syntax for defining Next.js routes using `fastify.next()`
- Can easily mix Fastify routes with Next.js pages:
  ```javascript
  fastify.get('/contacts', (req, reply) => {
    reply.type('html').send('<h1>Contacts page</h1>');
  });
  ```

## Important Considerations:

- Custom servers (Express or Fastify) cannot be deployed to Vercel or Netlify
- Lose some optimization benefits of Vercel's platform
- Can still use other hosting providers like DigitalOcean, Heroku, AWS, or Azure

The Fastify integration provides a cleaner, more performant alternative to Express.js for custom Next.js server implementations while maintaining all Next.js functionality.
