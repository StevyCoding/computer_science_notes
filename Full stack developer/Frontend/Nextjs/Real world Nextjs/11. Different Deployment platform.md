# Chapter 11: Deployment Platforms for Next.js

## Key Deployment Options

### 1. Vercel

- **Optimal choice for Next.js** (created by the same team)
- Supports all rendering methods through serverless functions
- **Deployment options**:
  * Git integration with automatic deployments and preview environments
  * Simple CLI commands (`vercel --prod`)
- Built-in analytics for monitoring Web Vitals
- **Limitation**: No support for custom Node.js servers

### 2. Netlify

- Similar developer experience to Vercel
- Automatic deployments from Git repositories
- Consider pricing differences when choosing between Vercel and Netlify

### 3. CDN for Static Sites

- **Benefits**: Global distribution, optimal performance, high availability
- **Popular options**:
  * **AWS**: S3 storage + CloudFront distribution (requires more configuration)
  * **Cloudflare Pages**: User-friendly UI with automatic Git deployments
  * **Azure Static Web Apps**: Integrates with GitHub workflows

### 4. Hybrid Deployments

- **serverless-next.js** enables optimal deployment architecture:
  * SSR pages/API routes → AWS Lambda
  * Static assets → S3 + CloudFront
- Best performance for each content type

### 5. Custom Server Deployment

- **Requires manual setup**:
  * Node.js runtime installation
  * Process manager (PM2) for reliability
  * Reverse proxy (NGINX/Caddy)
  * Firewall configuration
  * CI/CD pipeline
- Maximum control but higher maintenance burden

### 6. Docker Containerization

- **Simple Dockerfile example**:
  ```dockerfile
  FROM node:16-alpine
  WORKDIR /app
  COPY . /app/
  RUN npm install && npm run build
  EXPOSE 3000
  CMD npm run start
  ```
- Deploy to any container service or Kubernetes cluster
- Consistent environments across development and production

## How to Choose

Consider these factors:

- **Team resources**: Smaller teams benefit from managed platforms
- **Rendering needs**: Static sites → CDN; SSR → Node.js runtime
- **Scaling requirements**: Auto-scaling vs. manual configuration
- **Existing infrastructure**: Integration with current cloud providers
- **Budget**: Managed platforms are convenient but potentially costlier at scale

There's no universal solution - each project's specific requirements should guide your deployment choice, balancing developer experience with operational needs.
