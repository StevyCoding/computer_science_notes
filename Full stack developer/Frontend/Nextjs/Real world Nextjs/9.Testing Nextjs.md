# Testing in Next.js Development

## Key Testing Phases:

1. **Unit testing** - Testing individual components and functions
2. **End-to-end testing** - Testing complete user flows and application behavior
3. **Integration testing** - Testing how components work together

## Important Points:

- Testing Next.js applications is similar to testing any React app or server-side framework
- Previous React testing experience is transferable to Next.js testing
- The chapter will cover:
  - Introduction to testing concepts and frameworks
  - Setting up testing environments
  - Using popular test runners, frameworks, and utility libraries

## Benefits of Testing:

- Reduces the introduction of new bugs
- Prevents breaking existing features
- Provides confidence in code quality before production deployment

Testing is a fundamental part of the development workflow that ensures your Next.js application remains stable and reliable as it evolves.

# Introduction to Testing in Next.js

## Three Essential Testing Phases:

### 1. Unit Testing

- Tests individual functions in isolation
- Verifies correct outputs for various inputs
- Ensures each function works as expected

### 2. End-to-End (E2E) Testing

- Simulates actual user interactions with the application
- Tests complete workflows (e.g., form submission, navigation)
- Verifies UI rendering and behavior
- Automates what would otherwise be manual browser testing

### 3. Integration Testing

- Tests how multiple functions and modules work together
- Ensures cohesive operation between different parts of the application
- Focuses on the connections between components rather than individual units

## Testing Approach for Next.js:

- Testing Next.js applications follows similar patterns to testing React or server-side frameworks
- Requires selecting appropriate test runners and libraries
- A test runner executes tests, collects coverage data, and displays results

## Popular Testing Tools:

- **Jest**: Primary tool for unit and integration tests
- **Cypress**: Specialized for end-to-end testing

All three testing phases are strongly recommended before deploying code to production to ensure comprehensive coverage and application stability.

# Writing Integration and Unit Tests with Jest in Next.js

## Project Setup:

1. Clone the boilerplate repo with a simple blog application
2. Install Jest: `yarn add -D jest`
3. Create `.babelrc` with Next.js preset:
   ```json
   {
     "presets": ["next/babel"]
   }
   ```
4. Add test script to `package.json`: `"test": "jest"`

## Important Note:

- Never place test files in the `pages/` directory as Next.js will try to render them as pages

## Writing Utility Function Tests:

```javascript
describe("trimTextToLength", () => {
  test('Should cut a string that exceeds 10 characters', () => {
    const initialString = 'This is a 35 characters long string';
    const cutResult = trimTextToLength(initialString, 10);
    expect(cutResult).toEqual('This is a ...');
  });
  
  test("Should not cut a string if it's shorter than 10 characters", () => {
    const initialString = '7 chars';
    const cutResult = trimTextToLength(initialString, 10);
    expect(cutResult).toEqual('7 chars');
  });
});
```

## Testing React Components:

1. Install React Testing Library: `yarn add @testing-library/react`
2. Create mock data for testing
3. Add JSDOM environment: `/** @jest-environment jsdom */` at the top of test files
4. Test component rendering and behavior:
   ```javascript
   describe('ArticleCard', () => {
     test('Generated link should be in the correct format', () => {
       const component = render(<ArticleCard {...article} />);
       const link = component.getByRole('link').getAttribute('href');
       expect(link).toBe('/articles/healthy-summer-meloncarrot-soup-u12w3o0d');
     });
     
     test('Generated summary should not exceed 100 characters', async () => {
       render(<ArticleCard {...article} />);
       const summary = screen.getByText(trimTextToLength(article.body, 100));
       expect(summary).toBeDefined();
     });
   });
   ```

## Key Jest Functions:

- `describe`: Groups related tests
- `test`: Declares and runs a test
- `expect`: Compares outputs against expected results

This approach allows for comprehensive testing of both utility functions and React components, though end-to-end testing (covered in the next section) is still needed to test full page navigation and API interactions.

# End-to-end testing with Cypress

## Setting Up Cypress:

1. Install dependencies:
   ```bash
   yarn add -D cypress start-server-and-test
   ```
2. Add scripts to `package.json`:
   ```json
   "cypress": "cypress run",
   "e2e": "start-server-and-test 'yarn build && yarn start' http://localhost:3000 cypress"
   ```
3. Create `cypress.json` configuration:
   ```json
   {
     "baseUrl": "http://localhost:3000"
   }
   ```

## Testing API Endpoints:

```javascript
describe('articles APIs', () => {
  test('should correctly set application/json header', () => {
    cy.request('http://localhost:3000/api/articles')
      .its('headers')
      .its('content-type')
      .should('include', 'application/json');
  });

  test('should correctly return a 200 status code', () => {
    cy.request('http://localhost:3000/api/articles')
      .its('status')
      .should('be.equal', 200);
  });

  test('should correctly return a list of articles', (done) => {
    cy.request('http://localhost:3000/api/articles')
      .its('body')
      .each((article) => {
        expect(article).to.have.keys('id', 'title', 'body', 'author', 'image');
        expect(article.author).to.have.keys('id', 'name');
        expect(article.image).to.have.keys('url', 'author');
        done();
      });
  });

  test('should return 404 when an article is not found', () => {
    cy.request({
      url: 'http://localhost:3000/api/article?id=unexistingID',
      failOnStatusCode: false,
    })
    .its('status')
    .should('be.equal', 404);
  });
});
```

## Testing Page Navigation:

```javascript
describe('Navigation', () => {
  test('should correctly navigate to the article page', () => {
    cy.visit('http://localhost:3000/');
    cy.get('a[href*="/articles"]').first().click();
    cy.url().should('be.equal', 'http://localhost:3000/articles/healthy-summer-meloncarrot-soup-u12w3o0d');
    cy.get('h1').contains('Healthy summer melon-carrot soup');
  });

  test('should correctly navigate back to the homepage', () => {
    cy.visit('http://localhost:3000/articles/healthy-summer-meloncarrot-soup-u12w3o0d');
    cy.get('a[href*="/"]').first().click();
    cy.url().should('be.equal', 'http://localhost:3000/');
    cy.get('h1').contains('My awesome blog');
  });
});
```

## Key Benefits of E2E Testing:

- Verifies that links between pages work correctly
- Confirms that the server serves the correct data
- Tests actual user flows through the application
- Validates UI rendering and content display

End-to-end testing complements unit and integration tests by ensuring the entire application works correctly from a user's perspective, testing not just individual components but complete workflows and interactions.
