# DI Dependency injection

**Dependency Injection (DI)** is a **design pattern** used in software development to achieve **Inversion of Control (IoC)** between classes and their dependencies. Instead of a class creating its own dependencies, these dependencies are **provided to the class from an external source**, typically by a **framework or container**. This approach promotes **loose coupling**, **easier testing**, and **better maintainability** by allowing objects to be replaced or modified without changing the class that depends on them. In Java, DI is commonly used in frameworks like **Spring**, where the container injects dependencies into components via **constructors, setters, or fields**.

# Inversion  of Control 

**Inversion of Control (IoC)** is a principle in software engineering where the control flow of a program is inverted compared to traditional procedural programming. Instead of the custom code calling libraries to perform tasks, the **framework or external entity** takes control of the program flow and calls the custom code when needed. This design principle shifts the responsibility of managing the flow and execution from the application itself to a framework or container, promoting **loose coupling** and making the application more modular and easier to manage.

In the context of **Dependency Injection (DI)**, IoC is realized by having the **framework/container** manage the creation and injection of dependencies into the classes, rather than the classes creating and managing their own dependencies. This leads to more **flexible, testable, and maintainable code**, as the application logic is decoupled from the dependency management logic

# Aspect oriented Programming

**Aspect-Oriented Programming (AOP)** is a programming paradigm that enhances modularity by allowing the separation of cross-cutting concerns, such as logging, security, and transaction management, into distinct units called aspects. This helps in managing concerns that affect multiple parts of an application without scattering code. AOP achieves this through concepts like join points (specific points in program execution), advice (code executed at join points), pointcuts (predicates matching join points), and weaving (linking aspects with application code). For instance, in Spring AOP, logging method execution times can be modularized into an aspect, improving code maintainability and readability by isolating cross-cutting concerns from business logic.
